# Phase 4: Warehouse and vehicle integration (file-level design, DRAFT for owner approval)
Base: branch `analyse`, HEAD cbe8715 (Phases 1-3 delivered). Sources: arch §8, §9.1, §9.2, §17.1, §19 Phase 4; phase-3-design D1-D10 + owner approval + delivery record; phase-2/phase-1 conventions.

## 1. Scope
Delivers: company- and branch-level warehouses, vehicle master data, each 1:1 with a StockLocation created in the same transaction; optional vehicle branch assignment with reassignment validation; deactivation/reassignment guarded by a stock-usage hook (inert until Phase 8/9, wired and tested now); permissions Company.Warehouses.* / Company.Vehicles.*.
Excludes: any stock table, posting, StockLocks lock order, LocationId columns (Phase 8); transfers (Phase 9); vehicle sales/loading (Phase 10); drivers/HR (arch §9.2); allocation-scoped visibility (Phase 5); Angular (Phase 11); company creation (Phase 6); BranchStore/Transit stay system-managed (StockLocationType.cs:57).

## 2. Decisions
D1 Subtype tables, as approved in phase-3 D3: `Warehouses` and `Vehicles`, each with `StockLocationId` (no polymorphic FK, arch §8 last para). StockLocation stays the single source of Code/Name/BranchId/IsActive for warehouses (no duplicated columns, no drift); Warehouses carries identity + ownership kind + audit only. Rejected: "location rows only" (contradicts approved D3, no home for future warehouse attributes) and "shared PK" (D3 names a StockLocationId column; separate Id keeps the API id stable if a warehouse is ever re-homed via a new location).
D2 Subtype integrity by composite FK: new `AK_StockLocations_CompanyId_Id_LocationType` (StockLocationConfiguration.cs:72 pattern). `Warehouses(CompanyId, StockLocationId, LocationType)` and `Vehicles(CompanyId, StockLocationId, LocationType)` → that AK, Restrict, navigation-less (phase-2 convention). Warehouses.LocationType CHECK IN ('CompanyWarehouse','BranchWarehouse'); Vehicles.LocationType is a shadow/const column, default 'Vehicle', CHECK = 'Vehicle'. Effect: same company, correct type, and the location's type becomes structurally immutable while referenced. The FK index is made UNIQUE (`IX_Warehouses_StockLocation`, `IX_Vehicles_StockLocation`) - equivalent to StockLocationId unique because StockLocationId determines the other two columns; no extra index.
D3 Ownership: warehouse BranchId lives on its location (CHECK CK_StockLocations_Type_Branch, StockLocationConfiguration.cs:94 already enforces BranchWarehouse ⇔ BranchId and the composite branch FK :84). Ownership kind and branch are immutable after create (deactivate + create new). Vehicle location BranchId is always NULL (phase-3 O-1); assignment = `Vehicles.AssignedBranchId` with composite FK `(CompanyId, AssignedBranchId)` → Branches(CompanyId, Id), MATCH SIMPLE, Restrict, `FK_Vehicles_Branches_CompanyId_AssignedBranchId`, index `IX_Vehicles_CompanyId_AssignedBranchId`.
D4 Codes. Warehouse Code: trim + upper-invariant, `^[A-Z0-9]+(-[A-Z0-9]+)*$`, 1-20 (fits location rule D1 of phase 3), immutable, = location Code. Vehicle: `VehicleNumber` normalised (trim, upper, runs of whitespace/hyphen → single '-'), same pattern, 1-20, immutable, = location Code; `IX_Vehicles_CompanyId_VehicleNumber` UNIQUE (includes inactive: reactivate instead of re-adding). Both pre-check `(CompanyId, Code)` against every StockLocation of the company (covers branch-store codes and TRANSIT) → 400 `Code` (field `VehicleNumber` for vehicles), never a DB violation (phase-3 delivery record). BranchService.CreateAsync check (BranchService.cs:70-73) now becomes live in the other direction - unchanged.
D5 Concurrency: create runs in `StockLocks.BeginAsync` + FOR UPDATE on the company row, the same lock BranchService takes (BranchService.cs:287-297), so code checks are serialised with branch creation. WP2 extracts that private method to `internal static CompanyLocks.LockCurrentCompanyAsync(db, ct)` and BranchService calls it (behaviour unchanged). Location + subtype row in one SaveChanges.
D6 Names: warehouse Name 1-150, unique per company among warehouses (case-insensitive, service-level; mirrors branch rule BranchService.cs:39). VehicleName 1-150 required (location Name requires it), not unique; location Name mirrors VehicleName on edit.
D7 VehicleType enum (Domain/Inventory/VehicleType.cs, string, varchar(20), CHECK): Van, Truck, Car, Motorcycle, ThreeWheeler, Other. Additions are non-breaking (string enum).
D8 Usage hook: Domain `Abstractions/IStockLocationUsage.cs`: `Task<StockLocationUsage> GetAsync(Guid stockLocationId, CancellationToken ct)`; `record StockLocationUsage(bool HasStock, bool HasOpenTransfers) { bool InUse => HasStock || HasOpenTransfers; }`. Phase 4 impl `Services/StockLocationUsageService.cs` returns (false,false) with a comment naming Phase 8 (balances) / Phase 9 (open transfers); scoped DI in Program.cs:93 area. Called by: warehouse deactivate, vehicle deactivate, vehicle reassignment (any change of AssignedBranchId, incl. to/from NULL). InUse → 400 (`IsActive` / `AssignedBranchId`) "Transfer, return or reconcile this location's stock first". Reactivation never consults it.
D9 Reassignment (arch §9.2): allowed via PUT when usage is clear; target branch must exist in company, be active, and `IBranchContext.CanAccess` (else 403 `branch_access_denied` via BranchLabels.cs:39); the location is never touched (BranchId stays NULL), so stock is never re-owned. No assignment-history table in Phase 4 (UpdatedAt/UpdatedByUserId only) - see O-3.
D10 Status: deactivation mirrors IsActive to the location in the same SaveChanges; reactivation of a branch warehouse requires its branch active (400 `IsActive`). Branch deactivation (BranchService.SetStatusAsync, BranchService.cs:147) is refused while the branch has active branch warehouses or active vehicles assigned (400 `IsActive`) - see O-1; SetStatusAsync also takes the company lock (D5) so this check cannot race a warehouse create.
D11 Visibility: company warehouses and all vehicles are visible to every member with View (consistent with the Phase 3 fix, StockLocationsController.cs:41-44); branch warehouses follow `CanAccess(owner)`; detail/edit/status on an inaccessible branch warehouse → 404. Creating a branch warehouse requires CanAccess(branchId) → 403. Branch columns come from `BranchLabels` (phase-2 D3), warehouse DTOs from an explicit join of two company-filtered roots (Warehouses ⋈ StockLocations), never a navigation chain (phase-1 §8).
D12 Permissions (ADR-13, module "Administration" like Company.Branches.*, PermissionCatalog.cs:32-35): Company.Warehouses.View/Create/Edit/Disable, Company.Vehicles.View/Create/Edit/Disable; Administrator via PermissionResolver; no grants to other roles. StockLocations.View description updated to include warehouses and vehicles (PermissionCatalog.cs:47); StockLocationsController stays read-only (writes go through the owners).

## 5. API / DTO contract
Warehouses (`api/v1/warehouses`):
- `GET ?branchId=&ownership=Company|Branch&includeInactive=false` [View] → `WarehouseDto[]` ordered company first, then branch code, Code. Bad `ownership` → 400 `ownership`; `branchId` validated per phase-2 D8 (403 `branch_access_denied`).
- `GET {id}` [View] → 404 unknown/foreign/inaccessible.
- `POST` [Create] `CreateWarehouseRequest(string Code, string Name, Guid? BranchId)` → 201 + Location. NULL BranchId ⇒ CompanyWarehouse. Errors 400: `Code` (format, used by any location of the company incl. branch codes and TRANSIT), `Name` (empty, >150, duplicate), `BranchId` (unknown in company or inactive); 403 inaccessible branch.
- `PUT {id}` [Edit] `UpdateWarehouseRequest(string Name)` → 200; Code/BranchId/ownership not editable.
- `POST {id}/status` [Disable] `SetActiveRequest(bool IsActive)` (existing record) → 200; 400 `IsActive` when usage InUse or branch inactive on reactivate.
- `WarehouseDto(Guid Id, Guid StockLocationId, string Code, string Name, string Ownership, Guid? BranchId, string? BranchCode, string? BranchName, bool IsActive, DateTimeOffset CreatedAt)`.
Vehicles (`api/v1/vehicles`):
- `GET ?assignedBranchId=&unassigned=false&vehicleType=&includeInactive=false` [View] → `VehicleDto[]` ordered VehicleNumber. `assignedBranchId` validated per phase-2 D8; bad `vehicleType` → 400.
- `GET {id}` [View]; `POST` [Create] `CreateVehicleRequest(string VehicleNumber, string VehicleName, string VehicleType, Guid? AssignedBranchId)` → 201; `PUT {id}` [Edit] `UpdateVehicleRequest(string VehicleName, string VehicleType, Guid? AssignedBranchId)`; `POST {id}/status` [Disable] `SetActiveRequest`.
- Errors 400: `VehicleNumber` (format, duplicate, clashes with a location code), `VehicleName`, `VehicleType`, `AssignedBranchId` (unknown/inactive, or usage InUse on change), `IsActive` (usage InUse); 403 target branch inaccessible.
- `VehicleDto(Guid Id, Guid StockLocationId, string VehicleNumber, string VehicleName, string VehicleType, Guid? AssignedBranchId, string? AssignedBranchCode, string? AssignedBranchName, bool IsActive, DateTimeOffset CreatedAt)`.
Service interfaces (Domain, WP1): `IWarehouseService.CreateAsync(CreateWarehouseInput, Guid userId, ct) → Warehouse`, `UpdateAsync(id, UpdateWarehouseInput, userId, ct) → Warehouse?`, `SetStatusAsync(id, bool, userId, ct) → Warehouse?`; `IVehicleService` same three. Null = not found (controller → 404). Branch-access checks live in the controller (as StockLocationsController), branch-active/usage checks in services.
StockLocations API: unchanged contract; new types appear with IsSystemManaged=false, CanSell true for Vehicle.
